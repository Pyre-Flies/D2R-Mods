### P1: ordinary remote transfers and identification still require authority

`QueueLegacyQuickMove`, the ordinary Shared Stash withdrawal branch and
`QueueQuickMoveToCube` in `plugin_main.cpp` submit through `runOnGameThread`.
`OnItemInteraction` queues single identification there, and
`QolNativeIdentify::RequestAll` queues `BeginBulk` there even in native mode.
`QolBulkStash::Ui` also requires the game scheduler. SDK `threads.h` explicitly
returns `Unavailable` for remote TCP/IP clients, and `item.h` forbids their SDK
mutation. Several transfer scheduling failures are silent, while tooltip hints
remain available. This explains remaining nonresponsive ordinary LB shortcuts;
it does not imply that every advanced-storage/native UI route fails.

The belt/ground UI routes cannot safely be generalized by changing these calls
to `runOnUiThread`: the underlying SDK operations remain authoritative. Each
remaining action needs its own guarded native client-request contract, or an
explicit unavailable state with matching shortcut hints. No such transfer or
identification support is claimed by this candidate.

### P2: discarded game callbacks can leave pending state stuck across games

SDK `threads.h` says a session change discards queued game work. The single-ID
path sets `s_IdentifyPending` before scheduling and clears it only in
`ExecuteIdentifyTask` or an immediate scheduling failure. A successfully queued
callback dropped at session exit never executes either cleanup path; later
identify shortcuts are consumed indefinitely while the plugin remains loaded.
Heap-backed `IdentifyRequest`, `MoveRequest`, Cube `Pending` and ground request
payloads likewise have no cancellation cleanup after accepted tasks are dropped.

The bulk identification and stash state machines can also remain busy if their
only queued continuation is a discarded game callback. Their timeout checks run
inside the callbacks, so a dropped callback cannot expire itself. A session
lifecycle cancellation mechanism should clear ownership/state and use generation
tokens so stale tasks cannot cancel or act on a new request. This is established
from the SDK contract and source; leaving/rejoining at that exact point was not
reproduced live. The correction is deferred from this input/belt candidate.
