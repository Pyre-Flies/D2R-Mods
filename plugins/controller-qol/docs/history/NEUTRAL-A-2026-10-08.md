The user reports neutral controller A should prefer chests, shrines, wells,
portals, waypoints and stashes over ground loot. On 2026-10-08, the active Ladder
configuration had `prioritize_chests=false`; all the other priority toggles were
true, with `portal_priority_distance=10`. Wells share `prioritize_shrines`.

The 17:45:48 startup log admits the shared class-getter E9 detour and reports
`portal=1 stash=1 waypoint=1 shrine=1 chest=0`, with contact/scoring/range hooks
enabled and diagnostics off. This establishes installation for that run, not
successful neutral-A selection in gameplay. It does not establish a regression
in online behavior or the mouse/controller pickup filter.

The local trial enables `prioritize_chests` and `portal_diagnostics`. The shipped
default remains unchanged. Existing diagnostics cover candidate contact/score,
Interact comparison and range extension. No new native path, hook or signature
is added for this investigation.

Current priority code acts on native Interact skill 357 comparisons; it does not
use the server item scheduler or `block_filtered_pickup` setting. The configured
ground-loot modifier suppresses priority so LB pickup retains ownership. Neutral
A only promotes enabled, supported objects that reach native selection and pass
its remaining checks. Ordinary chest and well class lists are explicit;
unsupported mod objects and other object-versus-object ordering remain native.
See `PORTAL-PRIORITY.md`, `STASH-WAYPOINT-PRIORITY-REV43.md` and `portal_policy.h`.

Live check: place ground loot beside each supported object, release LB, and use

The original Selected entry is already documented in the aim module. This
extension checks the same original 32 bytes before aim installs its hook, then
calls the current entry at runtime to retain installed hook chains. The captured
image contains a QOL detour there, so original entry bytes come from existing
reviewed `aim/native_profile.h`, not that capture. Exact guards and provenance:
`interaction-priority-evidence.json`, `interaction_priority_signatures.h`.

### Narrow recovery

Run original GetInteractionTarget once and keep any nonnull result. On null only,
with active extension, known controller UI, valid player index and released
configured ground-loot modifier, re-query current native Selected for Interact
357. Promote only an enabled, supported priority object within the configured
native distance. Null/rejected selection, ground item, monster/NPC, unsupported
object and disabled kinds stay null.

The query reruns native selection rather than retaining a pre-arbitration pointer
from Compare, preserving the selected function's current hook chain and final
result. Player/candidate pointers are synchronous call locals. Reentrant recovery
is suppressed while querying. No world scan, new thread, packet, object operation
or shared record modification. The game owns movement and activation.

Admission is separate from existing priority hooks. Entry/body conflicts disable
combat recovery but retain object-versus-loot priority. Mouse UI, LB pickup and
existing results pass through; combat skills are not globally rescored.
Diagnostic `Neutral interaction recovered after combat arbitration` records kind
and distance at most once per second. It reports selection, not chest activation.
