# Narrower hook review — 2026-09-26

Static review of QOL rev.6 source and Item Roll Ranges current local source, plus the prior mapped-game capture. Recommendations only; no executable changes or live validation in this review. User reports rev.6 works with Chronicle; no claim of exhaustive load-order tests.

## Recommended priorities

1. **QOL portal contact, game 0x34BC90:** strongest direct-call candidate. Current CandidateContact invokes original, then modifies only return sites 0x19158E, 0x1922D2, 0x19237D. The capture confirms direct calls at 0x191589 (`E8 02 A7 1B 00`), 0x1922CD (`E8 BE 99 1B 00`), 0x192378 (`E8 13 99 1B 00`), all targeting 0x34BC90. A wrapper at each call could invoke the shared entry, preserve other owners' effects and apply the existing portal-only policy. This trades one broad hook for three narrower patches; it is not automatically less patch maintenance. Revalidate current bytes, full argument setup, and all three acquisition branches before migrating. Test neutral portals at 6/10/20 units and LB loot exclusion.

2. **QOL pickup, game 0x471950:** worth tracing, not yet a proven call-site replacement. Current hook suppresses native pickup under the loot modifier and pickups lacking a visible label, but exempts plugin-origin calls via TLS/caller recognition. Targeting the native controller interaction path could reduce collisions and remove part of that origin heuristic. However, the filtered-item rule may intentionally cover more native paths than controller A; establish keyboard/mouse and plugin semantics first. Also replace live-byte self-matching admission with a fixed qualified contract. No candidate caller RVA is asserted by this review.

3. **Item Roll Ranges Core slots:** good separate backlog, consistent with the previously deferred predecessor-hardening work. Wrappers already scope behavior by qualified return address while globally replacing slots. Source sites: Core key return 0x8195E0, pad 0x81995A, properties 0x81D53B, special ED 0x3E7FD6, range helper 0x3E80B2/0x3E80FD, single formatter 0x3E82EA. These are return addresses, not automatically patch-start RVAs. Core provider witness explicitly shows pad indirect CALL at 0x819954 (6 bytes); the actual call forms/relocation rules for each site must be reviewed. A wrapper should call through the current slot where appropriate to preserve other owners rather than bypass their adapter. Public SDK PatchBytes targets the game module; Core call patching needs a supported provider patch contract or careful separate ownership/lifetime machinery, so this is not an equally easy copy of the QOL fix. Properties rendering intentionally invokes range/actual passes; cooperative side effects need review. No IRR changes authorized by this review alone.

4. **QOL 18 action observers:** large shared-hook surface, but do not blindly replace each with a call patch. ActionHooks observes native packet handlers after predecessor execution and deliberately leaves the shared packet table free for potion pickup. Prefer establishing whether supported events/game-thread lifecycle context can replace the observation requirement. Verify game/player provenance and pending pickup scheduling before removing observers. A common dispatcher interception is also broad and may change before/after semantics; no specific replacement is yet qualified.

## Keep unless evidence justifies a change

- Native input event/reset 0x13EDD0/0x13DEF0: intentionally central; uniform world/UI input and disconnect/reset coverage are requirements. A tooltip/query-only path was already rejected. A public cooperative input service is a better replacement than a narrower incomplete call chain.
- Scoped BankPanel 0x23CAA0 and skill handler 0x14C6810 are already context-specific. A UI dispatcher may use virtual/indirect calls; searching for a direct CALL alone can miss paths. TabBar 0x878D30 is broader and merits scoping review, but no replacement is yet verified. Existing public UI events must be proven early enough to prevent native selection before substituting them.
- Label press/release 0xC66A0/0xC6E90 intentionally manage paired label behavior; replacing only one caller risks lost release/reset coverage.
- Portal scoring/range/comparison 0x18B350/0x18AED0/0x18A650: range is already semantically limited by TLS comparison context, but still claims a shared entry. Trace a comparison-owned call if needed; scoring/acquisition/comparison jointly fixed the extended-range behavior, so preserve the whole pipeline.
- Prompt widget 0x86D410 establishes scoped context for two text call patches. Removing it requires an equivalent reliable way to identify the widget. Shared renderer 0x902E20 is already unmodified.
- Materials, shared transfers, belt and selling primarily use qualified native calls/state rather than extra detour entries in those modules. Different entry points do not remove their layout/version dependencies.

## Decision rule

Use a narrow caller when it covers all required behavior, preserves original call/return and other owners, and has manageable lifetime/patch rules. A return-address whitelist inside a broad hook is a strong candidate signal. It is not proof: direct versus indirect dispatch, additional Core callers, resets, side effects and partial-install rollback still matter. Narrow call patches reduce entry collisions, not all semantic conflicts or patch fragility. Keep production baselines and migrate one feature at a time.
